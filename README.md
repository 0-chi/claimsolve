# クレソル(ClaimSolve)

企業の「クレーム対応」を評価するレビューサイト。カスタマーサポートのOpenWork。
本リポジトリは要件定義書 **v2.9** + **マーケティング設計書 v1.5**(`docs/marketing-v1.5.md`)に基づく MVP 実装です。

### マーケティング設計書 v1.5 の要点(実装済み)

- **live_enabled は初期値ON**(緊急停止用のOFF切替は維持)。liveが約束するのは「記録+通知」まで(解決は約束しない)
- **通知の正直表示(3状態)**: 登録済み / 通知先あり未登録 / **通知先不明**(「通知します」と言わない)。全状態に「運営の確認のうえ公開・通知します」
- **188案内の常設**: live完了画面・投稿者専用ページ・LP・記事に「まず公的窓口へ。その記録を、ここに」
- **消費者LP(`/`)**: gate OFF時はLP構成(対比表1行目=あっせん/silent導線/早期特典は本文100字以上のレビュー限定)、gate ONで検索主役に切替
- **企業LP(`/business`)**: `?from=notice`(通知メール経由)のときのみ「届いています」と表示。クレカ必須・削除窓口導線を明記
- **記事5本**(`/guide/articles/*`): A型×2(センター相談前・188)/B型×2(引越し・美容)/C型×1(サブスク解約)
- **公開投稿0件の企業ページは生成もインデックスもしない**(staffは数えない)。検索は法人マスタから「最初の1件」CTAカード
- **OGP**: 企業ページ(スコア+件数)・解決シェアカード。staff/silentには生成しない
- **GA4/Search Console**: env(`NEXT_PUBLIC_GA_ID` / `NEXT_PUBLIC_GSC_VERIFICATION`)設定時のみ読込。外部送信規律はプライバシーポリシーに記載
- **公開の前提条件**: 架空シードの撤去(`docs/marketing-v1.5.md` §10)

- **メイン=過去レビュー(past)**: 終了済みトラブルの対応を構造化評点でレビュー。企業参加ゼロで成立する集客・SEOエンジン。
- **サブ=ライブ案件(live)**: 進行中トラブルを企業に通知し、非公開スレッドで解決を目指す。**フル実装済みだが初期状態は非公開(`live_enabled=OFF`)**。
- **第3=サイレント(silent)**: 企業に一度も言わずに終わった不満を「なぜ言わなかったか」とともに記録。**告発ではなく自己申告**。AR には算入せず、**沈黙率(SR)/窓口不達率(UR)** という独自指標になる。
- **第4=担当者への申し出(staff)**: 特定の担当者の対応についての記録。**完全非公開**(公開ページ・sitemap・検索に一切出ない)。本文を読めるのはライトプラン企業のみ(無料企業にも着信と件数は通知)。**個人の処罰ではなく傾向把握が用途**。スコア非算入。

### 設計原則(v2.6以降の全機能の判断基準)

**企業が対価を払って買えるのは「自分について語る権利」だけ。「相手(投稿者)の状態を宣言する権利」は売らない。**

- 対策バッジ(80字以上・企業の自己申告)= 自分について語る → 売る(ライトプラン)
- 解決の申し出(1投稿1回・話しかける権利)= 自分について語る → 売る(ライトプラン)
- 「参考になった」マーク(企業の受け止めの表明)= 自分について語る → 売る(ライトプラン)
- **解決済みバッジ(投稿者の納得の宣言)= 相手の状態 → 投稿者だけが無料で確定。企業はAPIレベルでも作成不可**
- 対策+解決済みの両方が揃ったときのみ「対策・解決済み」完全バッジ(金銭では買えない)

> ⚠️ 投入されるシードは**すべて架空のデモデータ**です(フッターに注記、本番投入時に削除)。

## 本番公開

**`DATABASE_URL` に PostgreSQL を設定すると自動で本番モード**(デモデータ・デモ表記なし、
実サービス接続)に切り替わります。手順・環境変数・費用は **`docs/production-launch.md`** を参照。

## 技術スタック

- Next.js 14(App Router)+ TypeScript
- Prisma + SQLite(開発。PostgreSQL 互換を維持)
- Tailwind CSS / next/og(OGP画像)/ Vitest(テスト)

### APIキー無しで一気通貫

外部サービスはすべて **インターフェース + モック実装**。APIキーが1つも無くても、
`past投稿 → 自動公開 → 閲覧権付与`、`live投稿 → 通知 → 返答 → 評価 → スコア反映` の
両方がローカルで動作します。

## フラグ(admin で切替)

| キー | 初期値 | 役割 |
|---|---|---|
| `gate_enabled` | OFF | 閲覧ゲート。**自動ONは運用停止中(読み放題)**。会員が増えたら `src/lib/flags.ts` の `GATE_AUTO_ACTIVATION` を true に戻すと >200 で自動ON(admin手動ONは常に有効) |
| `monetization_enabled` | OFF | 課金開始。個人閲覧プラン(150円)の表示・販売を制御 |
| `live_enabled` | **OFF** | ライブレーンの全導線。ONで即座に有効化 |

- ゲートとの独立: ゲートONでも課金開始前は全件閲覧の解放手段は「投稿」と「シェア」のみ。
- ゲートON以前に発行された **review由来** ViewPass の有効期限は「ゲートON日から1ヶ月」に読み替えます。

### 閲覧権(ViewPass)の解放手段

| 手段 | 有効期限 | ウォッチ枠 | 条件 |
|---|---|---|---|
| レビュー投稿(past・本文100字以上) | 1ヶ月 | +1社 | — |
| 沈黙レポート投稿(silent・本文50字以上) | 3日 | — | — |
| 担当者への申し出(staff・本文80字以上) | 24時間 | — | — |
| 個人閲覧プラン(150円) | 契約期間中 | 5社 | `monetization_enabled=ON` |
| シェア | 24時間 | — | 7日に1回・便益明示の固定文言(編集不可)・金銭的報酬なし |

複数の閲覧権が重なる場合は**最も遅い有効期限**を採用します。

## スコア(第7章)

- MA=納得度平均 / RS=解決到達率(no_action以外)/ IN=また使う率 / IR=ライブ返答率
- `AR = (IR×2 + MA×10×3 + RS×3 + IN×2) ÷ 100`(0〜10)
- IR計算不能時: `AR = (MA×10×3 + RS×3 + IN×2) ÷ 80`
- レビュー5件未満は「集計中」。集計対象は直近24ヶ月(全期間タブあり)。
- 納得度の下限が4のため **ARの理論下限は0ではなく約1.2**(IRなしの場合1.5)。バッジ表示・軸設計はこれを前提とします。

### silent 指標(AR とは別枠)

- **SR(沈黙率)= silent ÷ (past+live+silent) ×100**。「◯%が『企業に一度も言わなかった』人からの報告」。総件数5件未満は「集計中」。
- **UR(窓口不達率)= 窓口不達(連絡先不明/繋がらない/返事が来ない)を選んだ silent ÷ silent総件数 ×100**。silent5件未満は「集計中」。企業ダッシュボードで3理由の内訳を表示。
- silent は Review を持たず、**AR には一切算入しない**。

### CR(対策報告率)— 常時公開・AR 非算入

- **CR = 対策バッジ付きの改善余地レビュー ÷ 改善余地レビュー総数 ×100**(改善余地=納得度6以下の past/live レビュー)
- 分母は消費者が決めるため、軽微な対策の量産では水増しできない。**取り消された対策報告の件数も併記**。
- 改善余地レビュー5件未満は「集計中」。
- 対策バッジ・解決済みバッジ・「参考になった」は **AR/SR/UR/CR いずれのスコアも動かさない**(バッジ捏造で点数は1点も上がらない)。
- staff レーンは **AR/SR/UR/CR とゲート判定(公開投稿数)のすべてから除外**。
- テスト: `scoring` / `gate`(200件境界・ViewPass期限合成) / `unlock`(7・14日) / `post-rules`(50・100字) / `share`(7日クールダウン) / `tests/past-flow`(統合)

## 外部サービス差し替え表(第12章)

すべて `src/services/index.ts` および `src/lib/moderation.ts` に interface + モックを実装。
本番では env を設定し、各ファクトリ関数の実装を差し替えます。

| 機能 | インターフェース | モック挙動 | 本番候補 | env |
|---|---|---|---|---|
| SMS認証 | `SmsService` | コード `123456` 固定 | Twilio 等 | `SMS_API_KEY` |
| eKYC(任意) | `KycService` | 3秒後に自動承認 | TRUSTDOCK 等 | `KYC_API_KEY` |
| 決済 | `PaymentService` | 常に成功 | Stripe | `STRIPE_SECRET_KEY` |
| メール送信 | `MailService` | コンソール出力+`EmailLog` | Resend / SES | `MAIL_API_KEY` |
| 投稿審査 | `ModerationService` | 正規表現+辞書 | Claude API | `ANTHROPIC_API_KEY` |
| 法人マスタ | `CorporateRegistry` | シード100社検索 | 国税庁 法人番号Web-API | `HOJIN_APP_ID` |

### 本番差し替え手順(例)

1. 対象 env を `.env` に設定。
2. `src/services/index.ts` のファクトリ(例: `smsService`)で、キーが存在する場合に本番クラスを返すよう分岐。
3. `ModerationService` は `getModerationService()` に LLM 実装を追加。
4. DB を PostgreSQL に切替える場合は `prisma/schema.prisma` の `datasource` を変更(スキーマは互換)。

## 原価メモ / 送信ドメイン

- SMS 約10円/通、eKYC 数十〜百数十円/件、LLM審査 数円/件。
- メール送信は **通知用ドメインとマーケ用ドメインを分離**する方針。
- 送信ドメインは **SPF / DKIM / DMARC** 設定を前提とする。

## 支払い方法の方針(企業向け)

- 月額払いはクレジットカードのみ(セルフサーブ)。
- **銀行振込(請求書払い)は年払い限定**。与信・請求・回収は掛け払いサービスへ外部化し、
  MVPでは未実装。**企業からの要望が出た段階で追加**(適格請求書=インボイス対応、
  特商法表記の支払方法欄を更新)。

## モデレーション / BAN(第8章)

- severe(脅迫・個人情報晒し・なりすまし)= 即BAN。
- warn 3回でBAN。BAN時は全投稿を非公開化し、同一電話番号での再登録をブロック。
- pastは自動公開+事後モデレーション(通報 or ソフト警告2件以上で admin キュー)。
